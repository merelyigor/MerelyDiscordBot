# Керівництво користувача: JSON-файли бота

Цей посібник пояснює, як налаштовувати поведінку бота через два JSON-файли:

| Файл | Що керує | Формат |
|---|---|---|
| `src/data/quotes.json` | Команда `/мотивація` (`/motivation`) | список цитат |
| `src/data/rules.json` | Відповіді бота на повідомлення в чаті | список правил |

Обидва файли — звичайний JSON: масив об'єктів. Після будь-якої зміни бота потрібно перезапустити
(зміни застосовуються при старті, «на гарячу» не перечитуються).

> Увага: JSON чутливий до синтаксису. Кожен рядок має відповідати формату нижче. Найчастіша помилка —
> пропущена кома між записами або зайва кома після останнього. Перевірити файл можна сервісом
> типу JSONLint або командою `node -e "JSON.parse(require('fs').readFileSync('src/data/quotes.json','utf8'))"`.

---

## 1. Цитати для `/мотивація` — `quotes.json`

Кожен запис — одна цитата:

```json
{
  "q": "Текст цитати",
  "a": "Автор"
}
```

- `q` (обов'язково) — текст цитати українською.
- `a` (обов'язково) — автор цитати.

Приклад двох записів:

```json
[
  { "q": "Геній — це 1% натхнення і 99% поту.", "a": "Томас Едісон" },
  { "q": "Ніколи не здавайся. Найтемніша ніч закінчується світанком.", "a": "Нельсон Мандела" }
]
```

Як це працює: коли користувач викликає `/мотивація @користувач`, бот випадково обирає одну цитату
з цього файлу і відповідає її текстом із тегом згаданого користувача.

Щоб додати цитати — просто вставте нові записи в масив перед закриваючою квадратною дужкою `]`.

## 2. Правила відповідей на повідомлення — `rules.json`

Кожен запис — одне правило «патерн → відповідь». Бот читає кожне нове повідомлення в чаті,
шукає перший збіг за патерном і відповідає.

```json
{
  "pattern": "патерн для пошуку",
  "type": "text",
  "response": "текст відповіді",
  "id": "необов'язкова назва",
  "channels": {
    "ключ": { "public": "ID каналу", "private": "ID каналу" }
  }
}
```

### 2.1. Поля

| Поле | Обов'язкове | Опис |
|---|---|---|
| `pattern` | так | Що шукати в повідомленні (див. типи нижче) |
| `type` | так | `text` — простий текст; `regex` — регулярний вираз |
| `response` | так | Текст, який бот надішле у відповідь |
| `id` | ні | Довільна назва правила для зручності (не впливає на роботу) |
| `channels` | ні | Підстановка посилань на канали в тексті відповіді (див. §2.3) |

### 2.2. Типи патернів

**`text` — простий текст, без урахування регістру.**

Спрацьовує, коли слово зустрічається в повідомленні (окремим словом, з пунктуацією теж):

```json
{ "pattern": "піська", "type": "text", "response": "Отваліська!" }
```

Спрацює на: `піська`, `Піська`, `ну і піська ж`, `піська!`.
Не спрацює на: `піськарня` (це інше слово, а не «піська»).

**`regex` — регулярний вираз.**

Дає більше гнучкості: послідовності, пропуски, варіанти слів. Регістр не враховується.

```json
{ "pattern": "всім\\s+офіснікам\\s+хай", "type": "regex", "response": "..." }
```

Спрацює на: `всім офіснікам хай`, `ВСІМ   ОФІСНІКАМ ХАЙ` (довільні пропуски між словами).

Короткий довідник регулярних виразів:

| Запис у `pattern` | Що означає |
|---|---|
| `\\s+` | один або більше пропусків (у JSON пишеться з подвійним слешем `\\`) |
| `\\s*` | нуль або більше пропусків |
| `хай|привіт` | «хай» АБО «привіт» |
| `.*` | будь-які символи |
| `офіснік\\w*` | «офіснік», «офісніка», «офіснікам» і т.д. |
| `(?:^\|\\s)` | початок повідомлення або пропуск |

> Якщо не впевнені у regex — використовуйте `type: "text"`, це найпростіший варіант.

### 2.3. Посилання на канали в тексті відповіді

Щоб бот підставив у відповідь посилання на канал, використовуйте плейсхолдер `{ключ}` у `response`
і опишіть канали в полі `channels`:

```json
{
  "pattern": "всім\\s+офіснікам\\s+хай",
  "type": "regex",
  "response": "всі офісніки чілять в офісі 💼 {офіс}",
  "channels": {
    "офіс": {
      "public": "1533165578867572836",
      "private": "1533165008484171986"
    }
  }
}
```

Як це працює:
- На місці `{офіс}` бот поставить `<#ID_каналу>` (Discord сам перетворить на клікабельне посилання).
- `public` — канал, який показується всім (за замовчуванням).
- `private` — «привілейований» канал: якщо автор повідомлення має до нього доступ, бот покаже його.
  Для голосового каналу доступ = права «Переглядати» + «Приєднатися»; для текстового = «Переглядати».
- Якщо автор не має доступу до `private` — бот покаже `public`.

Ключ у `response` і ключ у `channels` мають **збігатися** (`{офіс}` ↔ `"офіс"`).

Як дізнатися ID каналу: у Discord увімкніть «Режим розробника» (Налаштування → Додатково),
натисніть правою кнопкою на канал → «Копіювати ID каналу».

### 2.4. Порядок правил і збіги

Бот перевіряє правила **по порядку** зверху вниз і використовує **перший збіг**. Якщо два правила
можуть спрацювати на одне повідомлення — спрацює те, що стоїть вище у файлі.

Приклад повного файлу `rules.json`:

```json
[
  {
    "pattern": "всім\\s+офіснікам\\s+хай",
    "type": "regex",
    "response": "всі офісніки чілять в офісі 💼 {офіс}",
    "id": "office-chanel",
    "channels": {
      "офіс": {
        "public": "1533165578867572836",
        "private": "1533165008484171986"
      }
    }
  },
  {
    "pattern": "піська",
    "type": "text",
    "response": "Отваліська!"
  }
]
```

## 3. Де розташовані файли та як вони потрапляють у роботу

- Файли лежать у `src/data/` всередині проєкту бота.
- При збірці (`npm run build`) вони копіюються в `dist/data/`; у Docker-образ вони потрапляють
  так само на етапі збірки.
- Бот читає їх **один раз при старті** і тримає в пам'яті до завершення.
- Тому після редагування файлів бота треба перезапустити, і лише в новій версії зміни будуть активні.

## 4. Типові помилки та перевірка

1. **Неправильний JSON** (зайва/пропущена кома) — бот не запуститься. Перевірте файл JSON-валідатором.
2. **Плейсхолдер не збігається з ключем у `channels`** — замість посилання користувачі побачать `{ключ}` як текст.
3. **`type` неправильний** — тільки `text` або `regex`.
4. **Порядок правил** — перший збіг виграє; розміщуйте специфічні правила вище.

Перевірка змін перед запуском:

```bash
node -e "console.log('quotes:', require('./src/data/quotes.json').length, 'rules:', require('./src/data/rules.json').length)"
```
